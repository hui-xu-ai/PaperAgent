# PaperAgent v1.3.0

> 本地单用户文献 AI 阅读 / 翻译 / 知识库管理应用（Windows 免装包 + 源码两种用法）。
> 上一个公开版是 v1.0.0；本版是**检索质量与知识库容量**的一次大迭代。

## 升级须知（先读这一段）

| 问题 | 答案 |
|---|---|
| 会丢数据吗？ | **不会。** `DATA_FORMAT` 保持 3，本版无迁移，首启不会动你的库。 |
| 要重新解析 PDF 吗？ | **不用。** 解析产物与知识库目录格式未变。 |
| 要重新编译吗？ | **不用。** `_note.md` / `_wiki.md` / `_relations.md` 全部沿用。 |
| 要动手做什么？ | **向量索引需要重建一次**（存储格式换了，旧格式不做读时兼容）。见下。 |

**向量索引重建**（二选一）：

- **推荐**：打开应用 → 知识库面板 → 点一次「重建向量索引」。会重新调用 embedding
  API（按篇数计费）；
- **零成本**：调用 `paperkb.db.import_legacy(get_index_store(roots))` 把旧向量一次性
  搬进新存储（不重新 embedding），导入后旧文件 `data/vector/kb_vectors/*.npy` 可删。

升级前照例备份 `data/` + `knowledge_base/`（`docs/UPGRADE.md`）。

## 本版亮点

### 检索质量（本版最大改动）

- **RRF 融合**替代早期硬编码分数相加：六路召回（笔记 FTS / 向量 / 元数据 / 引用邻域 /
  卡片 / 附件全文）只比排名不比原始分（余弦与 BM25 本就不可比）；
- **二阶段精排**：`bge-reranker-v2-m3` 交叉编码器对候选池重排（可关，失败静默降级）；
- **small-to-big 注入**：向量按 900 字块匹配，注入时扩到所属小节整段（≤1200 字）；
- **产物整份优先**：编译产物按整份注入而不是片段——修掉「数值被截断」这类硬切问题
  （实测片段会在 570 字处把「研究结果」的做功密度、等长应力全切掉）；
- 新增 `textseg` 切分原语、查询向量缓存、检索质量三档消融评测与回归门。

### 知识库容量（10 万 / 50 万篇）

- 向量存储从「每次编译重写整份 npy」改为**段式追加写 + manifest + 原子压实**；
- 消除真实的 O(N²) 写放大，索引改块级 + 内容 md5 增量刷新；
- 进程级单例 + SQLite 命名索引；新增**索引健康四接口**与**死信重试**。

### 编译与显示

- **不再虚报「已完成」**：产物被清理后界面显示「待重建」而不是继续写「已完成 L3」；
- **L3 自动升级**修掉「陈旧完成记录永久挡掉重建」；
- 期刊名匹配三级兜底（ISSN → 名称规范化 → 城市消歧后缀），实测 120 篇只能靠刊名匹配
  的文献命中数 118 → 120；
- `_relations.md` 相关文献补编号、wikilink 一律用目录名（修 Obsidian 死链）。

### 其他

- 文献计量图谱：聚类分析、体积斥力防重叠、节点大小缩放、被引来源选择；
- 设置：MinerU 模型版本选择器 + 4 个 API 路径可配置；
- 前端 `app.js` 拆分为 10 个功能模块；KB 管理弹窗重写；
- 新增 `kb_paper_products` agent 工具（模型可主动取整份编译产物）。

## 下载即用

1. 下载 Assets 里的 **`PaperAgent-v1.3.0-win64.zip`**（免装 Python）；
2. 解压到**空目录**（别放 C 盘只读位置）；
3. 双击 `PaperAgent.exe` → 「设置中心」填 Key：
   - `MINERU_API_KEY`（解析必需，<https://mineru.net/apiManage> 免费申请）
   - `DEEPSEEK_API_KEY`（翻译 / 编译 / 问答必需）

数据、密钥、文献都在**解压目录内**（`data/ library/ knowledge_base/ .env`），
升级只覆盖 `PaperAgent.exe` + `_internal/`。

## 已知限制

- 仅 Windows；单用户本机应用（只监听 127.0.0.1，**无鉴权**，勿暴露公网）；
- 解析依赖 MinerU 网络；翻译/编译/问答依赖 OpenAI 兼容 LLM；
- **仍未覆盖 ISO 缩写期刊名**（`J. AM. CHEM. SOC.` 这类），需要 JCR 缩写列数据；
- 检索评测集仍是合成标签，真实结论需人工标注 50~100 条问句；
- ANN 索引（HNSW/IVF）未做——10 万篇以内走全量精确检索；
- 主题 MOC（`_topics/`）与「索引健康」前端卡片尚未实现（后端接口已就位）。

完整变更见仓库 `CHANGELOG.md`；知识库架构与设计哲学见 `docs/KNOWLEDGE-BASE.md`。
