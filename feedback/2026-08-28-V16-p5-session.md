## 一、步数膨胀根因（本会话排序）

| 根因 | 证据 | 浪费轮次 |
|---|---|---|
| ① **子代理等待轮询**：9+ 子代理每个 10-30 分钟，我反复 `Start-Sleep + 查报告文件/git log`（部分 Sleep 超时被截断重查）——等待无产物，纯上下文成本 | E1/E2/FB/E3/分页 5 个子代理各等 5-15 分钟，轮询 5-15 次 | 60-100 |
| ② **单会话无交接**：A/E1/E2/FB/E3 五阶段一鼓作气，前缀线性增长 | 用户 5 次"继续"，我 5 次未主动交接 | O(N²) 全放大 |
| ③ **backend 手动重启**：每次 Python 改动 → 杀 PID + Start-Process + sleep + 探活（20+ 次） | 无 uvicorn --reload、无重启脚本 | 30-40 |
| ④ pwsh 内联 python 引号失败 3 次才全改脚本文件（V14/V15 已提，仍未"第一次就写文件"） | dbg_*.py 5+ 个 | 8-12 |
| ⑤ 记忆反复整段替换（SHORT-TERM 每次 edit 都要先 read 全文） | fs 策略 read-before-edit | 10-15 |

**结论：步数多 = 子代理等待无预算（应"委派后主线做独立工作/任务化等待"）+ 单会话无交接
+ backend 重启基建缺失 + pwsh 内联禁令未真正执行。** 本会话子代理交付好，但**等待成本抵消
了委派收益**——委派的价值只在"主线不等"时成立。
